# InkCanvas

A OneNote-style notebook app with an infinite pan/zoom canvas, built in
Flutter so the same codebase runs on Windows and Android. This is an MVP:
the core canvas and navigation are fully implemented and usable; a few
things are intentionally left for later (see **Known limitations**).

## Getting it running

This folder contains only the Dart source (`lib/`) and `pubspec.yaml` —
the platform-specific `windows/` and `android/` folders that a real
Flutter project needs are generated by the Flutter CLI, not hand-written,
so you'll create them once on your own machine (they aren't something an
AI should hand-write blind, since they're boilerplate that the `flutter`
tool knows how to keep in sync with your installed SDK).

1. Install Flutter (if you haven't already): https://docs.flutter.dev/get-started/install
   Make sure `flutter doctor` is happy for both Windows desktop and
   Android (Android Studio + an SDK/emulator or a physical device).
2. From *inside* this folder, run:
   ```
   flutter create --platforms=windows,android .
   ```
   This adds `windows/` and `android/` around the existing `lib/` and
   `pubspec.yaml` without touching them.
3. Fetch packages:
   ```
   flutter pub get
   ```
4. Run it:
   ```
   flutter run -d windows
   flutter run -d <your-android-device-id>   # flutter devices to list
   ```

Windows desktop support needs to be enabled once per machine if it isn't
already: `flutter config --enable-windows-desktop`.

## Feature tour

- **Notebooks > Sections > Pages**, same shape as OneNote — colored
  section tabs, a page list per section, editable titles.
- **Infinite pan/zoom canvas** — the core ask. Pan and zoom are just two
  numbers (an offset and a scale) with no bounds, so there's no fixed-size
  "board"; see `lib/canvas/canvas_viewport.dart`.
- **Pen tool** with pressure-sensitive ink (uses stylus pressure when the
  device reports it).
- **Highlighter** (wide, translucent, multiply blend).
- **Eraser** (whole-stroke eraser — see limitations).
- **Shapes**: rectangle, ellipse, line, arrow.
- **Lasso select** — draw around content to select it, then drag to move
  or delete.
- **Text boxes** — tap with the Text tool to drop one down and start
  typing immediately.
- **Insert image** — from a file, on both Windows and Android (via
  `file_picker`, which supports both).
- **Undo/redo**, per page.
- **Page background**: plain, lined, or grid.
- **Local-only storage** — everything is saved as JSON on-device
  (`lib/storage/local_store.dart`); nothing leaves the device. No sync
  between your Windows PC and Android device yet (see limitations) —
  that was left out of this pass on purpose so we could get the core
  canvas right first.

## How the infinite canvas handles input

This was the trickiest part, so it's worth explaining the rule set (also
commented at the top of `lib/canvas/infinite_canvas.dart`):

- **Stylus (pen)** always performs whatever tool is active — draw, erase,
  shape, lasso, place text, or select/move. The pen's eraser end
  (`invertedStylus`) always erases, regardless of the selected tool,
  matching real pen hardware.
- **Touch (finger)**: one finger pans, two-or-more fingers pinch-zoom —
  *always*, regardless of tool — except when the **Select** tool is
  active, where one finger taps/drags to select and move content instead
  (a second finger arriving mid-gesture still takes over as pinch-zoom).
  The **Text** tool also accepts a single-finger tap, so you can place a
  text box on a touch-only device with no stylus.
- **Mouse**: left-button drag performs the active tool's action;
  middle- or right-button drag pans; the scroll wheel zooms (holding
  Ctrl) or pans (plain scroll).

Ink, shapes, and the pan/zoom math all live in *canvas-space* coordinates
that never change; only the on-screen mapping (`CanvasViewport`) does.
That's what makes ink keep its true size relative to the page as you
zoom, exactly like OneNote/Samsung Notes.

## Project layout

```
lib/
  models/         Notebook, Section, Page, and canvas element types
                   (ink stroke, text box, image, shape) — plain Dart,
                   hand-written toJson/fromJson (no code generation).
  storage/         LocalStore: on-device JSON persistence.
  state/           LibraryController: the whole in-memory library +
                   current notebook/section/page selection.
  canvas/          The infinite canvas itself: viewport math, the
                   PageEditController (tools, undo/redo, selection),
                   the CustomPainter, and pointer-routing widget.
  ui/              Screens: notebook grid, notebook (sections/pages/
                   canvas), page. ui/widgets/ has the toolbar and color
                   palette.
```

## Known limitations (this MVP pass)

These were left out deliberately to keep this pass focused on getting
the canvas interactions solid, per your steer to build the MVP scaffold
first:

- **No sync between devices.** Each device keeps its own local library.
  When you're ready, a sync layer (either the same direct USB-C/Wi-Fi
  approach as your Notes Ink project, or a cloud backend) can be added
  without touching the canvas/model code — it would just need to read and
  write the same `Notebook` JSON.
- **Eraser removes whole strokes**, not partial segments — dragging the
  eraser across part of a stroke deletes the entire stroke, not just the
  part you touched.
- **No image/shape resize handles** — images and shapes can be moved (via
  the Select tool) but not resized after placement, other than by
  deleting and re-inserting.
- **No search, tags, or export** (PDF/print) yet.
- **No rich text formatting** (bold/italic/lists) inside text boxes —
  plain text only.
- **Undo/redo is per-page** and resets when you navigate away from a page
  (it isn't persisted to disk).

## A note on this build environment

This project's Dart source was written and carefully reviewed by hand,
but `flutter pub get` / `flutter analyze` / an actual build could not be
run in the sandbox this was built in — its network access is restricted
to a small allowlist that doesn't include the hosts the Flutter/Dart
tooling downloads from. The code has been checked closely (bracket
balance verified programmatically, every file re-read line by line,
several API assumptions double-checked against Flutter's docs), but you
should still run `flutter analyze` right after `flutter pub get` as your
first step on your own machine, before assuming everything is 100%
correct — treat it as a thorough first draft, not a compiled artifact.
